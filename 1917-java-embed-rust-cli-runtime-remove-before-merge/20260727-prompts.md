## Summary

**Spike `spike-3-11-replay-proxy-and-in-process`** created and run successfully on win32-x64 (JDK 25.0.2, JNA 5.19.1, `runtime.node` 1.0.73). The spike proved a complete InProcess ping–pong round trip in 1.1 s and answered all five questions in §3.11.

**Key findings (all now codified in the Resolution):**

1. **The replay proxy CAN work with InProcess transport.** The native runtime reads `COPILOT_API_URL` from the live Win32 environment block (not Java's `System.getenv()` snapshot). Java must call `SetEnvironmentVariableW`/`setenv()` via JNA — there is no stdlib API for this.

2. **`InProcessEnvGuard`** (new class in `spike-3-11`) is the Java equivalent of Rust's `InProcessEnvGuard` and .NET's `InProcessEnvIsolation`. It calls `kernel32.SetEnvironmentVariableW` on Windows and `libc.setenv()` on Unix via JNA, saves current values, applies overrides, and restores on `close()`. **PASS confirmed on win32-x64.**

3. **Runtime.node ABI version sensitivity** (bonus finding): version `1.0.69-0` is missing `copilot_runtime_host_start`; version `1.0.73` has both the old and new APIs. 5. **`@SkipInProcess` annotation** needed for tests that rely on per-client environment variables (see issue #1934).
