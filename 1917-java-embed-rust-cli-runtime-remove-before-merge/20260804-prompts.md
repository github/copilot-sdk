There is no universal validity check for a generic `Password` alert. For an identified, authorized credential, use a harmless read-only request with the value supplied through a secure environment variable—never paste it into a command or file:

A `200` generally means valid; `401` means invalid or revoked. For Azure OpenAI, use the specific resource endpoint and `api-key` header. For GitHub tokens:

Use provider audit logs or credential-management pages where possible instead of probing production. Then create a replacement credential, update every consumer, test with the replacement, revoke the exposed credential, and only afterward resolve the Secret Scanning alert.
