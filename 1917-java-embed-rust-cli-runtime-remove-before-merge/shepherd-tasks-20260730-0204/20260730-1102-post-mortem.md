## Section 7: Failure Analysis

### 7.1 Root Cause: Phase 2 Duration Exhausted Run Budget

**Symptom:** Script exit code 1; no phase artifacts exist for issues [#2146](https://github.com/github/copilot-sdk/issues/2146)–[#2151](https://github.com/github/copilot-sdk/issues/2151).

**Evidence:** Phase 2 for [#2145](https://github.com/github/copilot-sdk/issues/2145) ran for 502m 51s (02:39 → 11:02), consuming the entire remaining run window. The script processes tasks serially; the first task with a deep review cycle effectively blocked all subsequent tasks.

**Root cause:** Issue [#2145](https://github.com/github/copilot-sdk/issues/2145) — "Native binary extraction and caching" — introduced substantive Java FFI implementation (`PlatformDetector`, `NativeRuntimeLoader`, tests). This triggered a medium-effort CCRA review with 7 actionable comments requiring local code fixes, test failures to diagnose and fix, and then extended CI polling that ran for several hours before checks passed. The serial shepherd script design offers no mechanism to time-box individual task phase sessions; a single slow task monopolizes the entire orchestration window.

**Impact:** 6/9 tasks ([#2146](https://github.com/github/copilot-sdk/issues/2146)–[#2151](https://github.com/github/copilot-sdk/issues/2151)) were never started, all remain OPEN.

### 7.2 Test Failures in Issue [#2145](https://github.com/github/copilot-sdk/issues/2145) Phase 2

**Symptom:** Maven test run against worktree `review-copilot-pr-2157` produced failures before the fix commit.

**Evidence from logs:**

```
[ERROR] Tests run: 17, Failures: 1, Errors: 1
[ERROR] com.github.copilot.ffi.NativeRuntimeLoaderTest.missingClasspathResourceThrows(Path) <<< FAILURE!
[ERROR] com.github.copilot.ffi.NativeRuntimeLoaderTest.resolveFallsBackToRuntimeNodeSibling(Path) <<< ERROR!
```

Three CCRA comments directly addressed these tests:
1. Test assertions used literal allow-list values instead of production classifier logic.
2. Tests reimplemented internal logic rather than calling production methods.
3. Environment variable handling in `NativeRuntimeLoader` was inconsistent.

**Resolution:** Commit `406ae3c9` ("Address Copilot review findings for FFI loader tests") fixed all three test issues. Post-fix Maven runs passed. All 7 CCRA review threads were resolved before merge.

### 7.3 Copilot Reviewer Collaborator Restriction

**Symptom:** `gh pr edit --add-reviewer copilot-pull-request-reviewer` returned GraphQL deprecation warnings; the direct API call failed with HTTP 422.

**Evidence:**

```
gh: Reviews may only be requested from collaborators. One or more of the users or teams 
you specified is not a collaborator of the github/copilot-sdk repository. (HTTP 422)
```

**Workaround applied:** The shepherd used `gh pr comment <PR> --body "@copilot review"` to trigger CCRA via mention instead of the collaborator reviewer API. This worked for all three PRs.

**Impact:** Minor — adds one extra API round-trip per PR but does not block convergence.

### 7.4 CCRA Unable to Review Structural PRs

**Symptom:** For [#2143](https://github.com/github/copilot-sdk/issues/2143) and [#2154](https://github.com/github/copilot-sdk/issues/2154), CCRA responded:

```
Copilot wasn't able to review any files in this pull request.
```

**Analysis:** Both PRs contained primarily Maven POM restructuring, build file moves, and `justfile`/workflow updates. CCRA may not analyze non-code files (XML, YAML, Makefile-style files) or may decline review when no Java source changes are present.

**Impact:** Neutral for these tasks — they passed CI and merged cleanly. However, this means CCRA provides no safety net for structural or configuration changes.

## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- All three processed tasks converged to merge without human intervention.
- The idempotent PR-finding strategy (three-strategy poll: timeline → body search → title/branch match) was reliable.
- CCRA's substantive review of [#2145](https://github.com/github/copilot-sdk/issues/2145) caught real bugs (integer overflow in ELF parsing, improper test isolation, environment variable ordering). The 7 comments were actionable and all were addressed.
- The sibling-worktree fix pattern (create `review-copilot-pr-2157`, apply fixes locally, push) worked end-to-end.
- Squash merge (merge commits disallowed in this repo) was handled correctly on the first fallback attempt.
- The `@copilot review` mention workaround for the HTTP 422 reviewer restriction was effective.

### 8.2 What Didn't Work Well

- **Serial task processing with no per-task time cap:** A single deep-review task ([#2145](https://github.com/github/copilot-sdk/issues/2145)) blocked 6 subsequent tasks for ~8.5 hours. This is the primary throughput bottleneck for the campaign.
- **502-minute CI polling in phase 2:** It is unclear whether CI checks genuinely took ~7 hours after the fix push or whether the phase 2 session entered a polling-dominated wait loop. The lack of explicit CI timestamps in the session log makes root cause ambiguous.
- **CCRA skipping structural PRs:** Build and configuration changes receive no automated review safety net, increasing risk for workflow or POM regressions.
- **No progress on tasks 4.4–4.9:** The campaign objective requires all 9 tasks. Completing 3/9 in this run (with the remaining 6 still OPEN) means a follow-up run is required.
- **Script exit code 1 with unclear trigger:** No phase-1 artifact was created for [#2146](https://github.com/github/copilot-sdk/issues/2146), suggesting the script exited before the first CCA assignment call for that task. The exact failure point is not captured in available logs.

### 8.3 Recommendations

1. **Add per-task phase timeout:** Cap each phase session at a wall-clock budget (e.g., 60–90 minutes). If the cap is hit, mark the task as `PARTIAL` and move to the next task; emit a warning artifact. This prevents one slow task from blocking the full batch.
2. **Parallelize phase 1 across tasks:** Phase 1 (CCA assignment + wait for PR) is independent across tasks and could be batched in parallel, reducing total wall clock for fast tasks.
3. **Log CI polling timestamps explicitly:** Add timestamped "still waiting at Ns" output to the CI polling loop so the post-mortem can distinguish "waiting for CCA to push" from "waiting for checks to run" from "runaway poll loop."
4. **Capture script termination reason:** Before the script exits with code 1, write a `script-failure-reason.txt` to the log directory so the post-mortem has a definitive root cause without inference.
