## Section 7: Failure Analysis

### 7.1 Primary Failure

The immediate failure was a bounded wait timeout. The re-review request succeeded, but CCRA did not post a review within 10 minutes. The script treated absence of a review by the deadline as fatal and exited before merge.

**Evidence:**

- Current `gh` reported a successful `pr edit ... --add-reviewer @copilot`.
- The polling loop checked both PR reviews and line-level Copilot comments.
- The loop terminated with `ERROR: Copilot review did not complete within 10 minutes`.
- The final shepherd message explicitly stated that the PR remained unmerged.

### 7.2 Contributing Factors

1. **The configured timeout was shorter than the external service's observed latency.** A successful asynchronous request was converted into a hard campaign failure after exactly 10 minutes.
2. **The installed GitHub CLI was too old for the supported `@copilot` reviewer flow.** Version 2.45.0 queried a deprecated Projects-classic field and failed before submitting the request.
3. **The initial REST fallback used the wrong reviewer model.** `copilot-pull-request-reviewer` resolves as an organization, not a collaborator user, so the REST endpoint returned HTTP 422 on all three attempts.
4. **Outcome signals differ across layers.** The caller exit code was `1`, while the exported session result carried `exitCode: 0`. Automation that reads only the latter could incorrectly classify the run as successful.

### 7.3 Root Cause Classification

|----------|------------|
| Code correctness | Not the observed blocker; known comments were fixed and CI was green |
| CCRA availability/latency | Primary external blocker |
| Shepherd timeout policy | Primary orchestration contributor |

## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- The shepherd correctly found and validated the issue/PR relationship and target base branch.
- It verified the actual review-thread state rather than assuming replies meant resolution.
- It confirmed broad CI success before attempting merge progression.
- It recovered from the obsolete local `gh` version by installing a current CLI in session-local storage.
- Polling remained blocking, avoiding an idle-session termination.

### 8.2 What Failed

- A successful review request was not durable across a timeout; the only result was campaign failure requiring manual intervention.
- The skill tried unsupported reviewer identities before using the documented `@copilot` flow.
- Tool compatibility was discovered during the critical path rather than checked at startup.
- The session result's zero exit code does not encode the semantic shepherd failure.

### 8.3 Recommendations

1. **Persist a resumable state after requesting review.** Record PR number, request timestamp, baseline review ID, and resolved-thread count so a retry can continue waiting without repeating completed work.
2. **Use a longer or configurable CCRA timeout.** Treat 10 minutes as an observation checkpoint, not an immediate terminal failure; use bounded backoff with a larger campaign-level deadline.
3. **Preflight `gh` capability.** Require a version supporting `--add-reviewer @copilot` before entering phase 2, or invoke a known-compatible bundled binary from the start.
4. **Remove the invalid REST fallback.** Do not submit `copilot-pull-request-reviewer` through the standard collaborator reviewer endpoint.
5. **Separate request failure from review latency.** Emit distinct failure signatures such as `REVIEW_REQUEST_FAILED` and `REVIEW_PENDING_TIMEOUT` so retries and post-mortems can classify them automatically.
6. **Propagate semantic failure into exported results.** Ensure a final `SHEPHERD FAILED` state produces a nonzero session result or an explicit machine-readable outcome field.
7. **Avoid repeating already-completed engineering work.** On retry, revalidate that `bc0275f8`, thread resolution, and green CI remain current, then resume from the second-review wait.

The safest recovery for this task is a phase-2 retry that recognizes the existing fixes and resolved threads, checks whether the delayed CCRA review has since arrived, and merges only after the required review state is satisfied.
