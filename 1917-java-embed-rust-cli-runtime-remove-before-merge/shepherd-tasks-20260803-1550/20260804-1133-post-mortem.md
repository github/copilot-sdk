## Section 2: System Architecture

The pipeline consisted of three collaborating agents:

### 2.1 Copilot Coding Agent (CCA)

Cloud-hosted agent (`copilot-swe-agent[bot]`) that receives issue assignments, creates feature branches, writes code, runs CI, and pushes commits. Triggered by the shepherd assigning the issue.

### 2.2 Copilot Code Review Agent (CCRA)

Cloud-hosted reviewer (`copilot-pull-request-reviewer`) that provides inline code review comments when requested on a PR. The shepherd iterates review rounds until approval or a maximum cap.

### 2.3 Local Copilot CLI (Shepherd)

Local `copilot-cli` v1.0.78-2 running `claude-opus-4.6` model. Orchestrates the two-phase pipeline:
- **Phase 1** (`shepherd-task-from-assignment-to-ready`): Assigns issue to CCA, approves CI workflows, waits for PR, validates it closes the correct issue, monitors CCA progress, marks PR ready.
- **Phase 2** (`shepherd-task-from-ready-to-merged-to-base`): Requests Copilot review, resolves review comments (re-engages CCA or resolves locally), iterates until approval, then merges.

## Section 8: Observations and Recommendations

### 8.1 What Worked Well

1. **100% success rate** — All 7 tasks merged autonomously with no human code changes.
2. **Efficient CCRA convergence** — Average 3.0 review rounds per task; no task hit a hard cap.
3. **Overnight autonomy** — The run spanned ~19.7 hours with zero human intervention.
4. **Serial dependency handling** — Each task correctly built upon the prior merged task's code on the base branch.
5. **Retry recovery** — The shepherd recovered from CCA failure on #2151 without manual intervention.

### 8.2 What Didn't Work Well

1. **#2151 phase 1 outlier** — 575 minutes (vs. median ~50 min) due to CCA "no effective changes" failure pattern. This single task consumed ~50% of total wall-clock time.
2. **High input token consumption** — Phase 2 for #2146 consumed 10M input tokens (most expensive session), likely due to large PR diffs and multiple review comment resolution cycles with 4 CCRA rounds.
3. **No parallelism** — Serial execution means total wall-clock scales linearly. Tasks 4.7–4.9 had no code dependency on each other but were executed serially.

### 8.3 Recommendations

#### For the Shepherd Orchestration Script

1. **Add a phase 1 timeout with escalation:** If phase 1 exceeds 120 minutes, notify the human operator (e.g., via webhook) rather than silently retrying. The 575-minute phase 1 on #2151 was recoverable but consumed excessive time.
2. **Consider parallel execution for independent tasks:** Tasks 4.7 (native download), 4.8 (E2E test), and 4.9 (CI workflow) could potentially run in parallel since they touch different file domains.

#### For the CCA (Copilot Coding Agent)

1. **"No effective changes" pattern:** The CCA should validate that its PR closes the assigned issue before marking completion. The re-engagement path works but adds hours of latency.

#### For the CCRA (Copilot Code Review Agent)

1. No issues observed — convergence was healthy across all tasks.

#### For the Local Copilot CLI Shepherd

1. **Token efficiency:** Phase 2 sessions with 4+ review rounds accumulate very large context windows (10M+ input tokens). Consider context compaction or session restart between rounds.
