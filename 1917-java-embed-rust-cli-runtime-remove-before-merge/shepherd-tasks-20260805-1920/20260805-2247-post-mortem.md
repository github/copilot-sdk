## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- The CCA produced a substantive draft PR and correct target base branch.
- The review request and one review round completed successfully.
- The shepherd applied review changes and achieved a later clean compile/format validation.
- Captured OTEL and session JSON artifacts provide reproducible timing, failure, and usage-checkpoint evidence.

### 8.2 What Did Not Work Well

- Phase 1 treated the missing completion event as a terminal timeout despite the PR being present and usable.
- The phase-2 validation path did not ensure the native runtime classifier was available to the selected tests.
- A long-lived phase-2 session was vulnerable to token expiration, with no recovery path before exit.
- The final result did not distinguish local build success from unresolved CI/test failures and merge readiness.

### 8.3 Recommendations

1. Add an explicit fallback in phase 1: when the PR exists, has the requested base, and CCA activity is complete enough, record the timeout as degraded completion and continue to phase 2 rather than requiring only `copilot_work_finished`.
2. Make Java test setup verify the native runtime artifact/classifier on the test classpath before running InProcess tests; fail with a focused diagnostic if absent.
3. Add session-token refresh/retry handling around long polling and model calls, with a bounded retry and a clear resumable outcome.
4. Require final `gh pr checks` and PR-state evidence before reporting merge success; preserve the failing check names and URLs in the task artifact.
5. Record per-message token fields when available, while retaining nano-AIU checkpoints as a clearly labeled fallback metric.
